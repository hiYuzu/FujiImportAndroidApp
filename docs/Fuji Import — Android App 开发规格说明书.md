# Fuji Import — Android App 开发规格说明书

**版本：** 1.0.0  
**项目类型：** Android 原生应用  
**开发语言：** Kotlin  
**UI 框架：** Jetpack Compose  
**开发方式：** Codex 辅助开发、ADB 实机调试  
**目标设备：** 小米 Pad 6S Pro  
**目标相机：** FUJIFILM X-T5

---

## 1. 项目背景与目标

开发一款专用于富士相机的 Android 照片浏览与导入工具，核心体验参考 iPhone 系统相册通过 USB-C 连接相机后的「导入」功能。

用户使用 Type-C 数据线直接连接富士 X-T5 和小米 Pad 6S Pro，打开 App 后即可浏览相机 SD 卡中的照片、查看大图、选择照片，并将原始文件导入平板。

应用不依赖富士官方 App，不依赖 Wi-Fi、蓝牙、云服务或互联网。

### 1.1 核心使用流程

1. 用户使用 USB-C 数据线连接相机和平板。
    
2. 打开 Fuji Import。
    
3. App 自动检测相机，按 Android 系统要求申请 USB 访问权限。
    
4. 连接成功后，自动读取相机照片列表。
    
5. 以系统相册风格展示照片缩略图。
    
6. 用户点击照片查看大图，或多选需要导入的照片。
    
7. 点击「导入」，将原始文件复制到平板。
    
8. 导入成功后，可在平板系统相册或文件管理器中查看相应文件。
    

核心体验应尽可能实现「插线 → 打开 App → 浏览 → 导入」，不要求用户每次连接时修改相机设置。

### 1.2 设计原则

- **实用优先：** 完成一个真正可长期使用的产品，而不是技术演示。
    
- **操作简单：** 尽可能减少无关设置、确认弹窗和中间步骤。
    
- **原图优先：** 导入时不压缩、不转码、不修改原始图片。
    
- **数据安全：** 对相机端只读，不修改或删除 SD 卡文件。
    
- **性能优先：** 大量照片场景下保持界面流畅，避免内存溢出。
    
- **离线运行：** 所有核心功能完全本地实现。
    
- **针对性适配：** 重点适配指定平板与相机，不要求兼容其他 Android 设备或相机品牌。

## 3. 核心功能需求

### 3.1 USB 设备连接与识别

**功能要求：**

1. App 启动时主动扫描已连接 USB 设备。
    
2. App 运行期间监听 USB 设备插入、拔出事件。
    
3. 自动识别支持 PTP/MTP 的相机设备，重点支持 X-T5。
    
4. 正确处理 Android USB 权限申请。
    
5. 授权成功后自动建立通信连接。
    
6. 读取相机基本设备信息和存储信息。
    
7. 支持 USB 断开后的资源释放及重新连接。
    
8. 不要求平板 Root，不依赖 ADB 实现 App 运行时的核心功能。
    

**连接状态：**

- 未连接相机
    
- 正在识别设备
    
- 等待 USB 授权
    
- 正在连接
    
- 已连接
    
- 连接失败
    
- 设备已断开
    

不同状态应有明确、简洁的中文提示。

优先支持 X-T5 当前用于 iPhone 照片导入的 USB 设置，不主动要求用户修改相机配置。只有检测出模式不兼容时才显示相应排查说明。

应考虑 Android 系统 MTP 服务或其他应用占用 USB 接口的情况，不能假设 USB 权限授权后一定能够打开设备。

### 3.2 相机照片扫描

连接成功后自动读取相机存储内容。

**要求：**

- 读取设备报告的全部可访问存储单元。
    
- 支持 X-T5 双 SD 卡槽的存储枚举。
    
- 递归扫描照片目录，不硬编码单一 DCIM 路径。
    
- 获取照片文件名、文件类型、大小、拍摄时间和所属存储单元等元数据。
    
- 自动过滤无关系统文件。
    
- 支持大量照片的异步扫描。
    
- 扫描过程中持续呈现已发现照片，不阻塞主界面。
    
- 提供手动刷新功能。
    
- 允许用户按卡槽筛选照片。
    

**优先支持格式：**

|格式|列表识别|预览|原文件导入|
|---|---|---|---|
|JPEG / JPG|必须|必须|必须|
|RAF（富士 RAW）|必须|尽可能支持|必须|
|HEIF / HIF|必须|设备支持时|必须|

同名 JPEG + RAF 应分别保留，不能因为基础文件名相同就忽略其中一个。可通过 RAW、JPG 等角标加以区分。

视频播放与导入不属于 1.0 的核心范围。

### 3.3 相册网格界面

这是 App 的主要界面，视觉与交互参考主流手机、平板系统相册。

**布局要求：**

- 默认采用网格布局。
    
- 优先适配平板横屏。
    
- 同时支持竖屏。
    
- 根据屏幕宽度自适应列数。
    
- 照片网格保持统一尺寸。
    
- 缩略图使用 Center Crop 填充。
    
- 图片间距适中，布局简洁。
    
- 支持连续纵向滑动。
    
- 支持按拍摄日期分组。
    
- 默认按拍摄时间倒序排列。
    
- 支持切换正序、倒序。
    
- 显示照片总数及当前筛选条件。
    

**加载要求：**

- 优先读取相机提供的缩略图。
    
- 异步加载可视区域图片。
    
- 使用内存及本地磁盘 LRU 缓存。
    
- 离开屏幕的图片及时释放相关资源。
    
- 快速滑动时不能因密集 USB 请求导致严重卡顿。
    
- 单张缩略图失败不应影响整个列表。
    
- 缩略图加载失败时提供占位图和重试能力。
    

优先保证已发现的照片能够尽快展示，不应强制等待全部扫描完成。

### 3.4 照片详情与预览

点击网格中的任意照片进入全屏预览。

**交互：**

1. 单击图片显示或隐藏工具栏。
    
2. 左右滑动切换上一张、下一张照片。
    
3. 双指缩放图片。
    
4. 双击放大或恢复。
    
5. 支持拖动查看放大后的局部。
    
6. 返回后保持原有相册滚动位置。
    
7. 在预览界面可直接选择、取消选择或导入当前照片。
    

**照片信息：**

可展开显示：

- 文件名
    
- 文件格式
    
- 文件大小
    
- 拍摄日期
    
- 分辨率
    
- 相机型号
    
- 焦距
    
- 光圈
    
- 快门速度
    
- ISO
    

上述信息仅在相机对象或可读取的 EXIF 元数据中存在时展示，不允许伪造缺失字段。

**预览策略：**

优先使用相机提供的预览图。如果清晰度不足，允许在用户进入大图页面时读取更高分辨率的数据。

对于需要完整 JPEG 文件才能解码高清图的情况，可以先下载至 App 私有临时目录，再使用采样解码或分块解码，避免整张高像素照片直接加载到内存。

对于 RAF 文件，优先尝试相机提供的缩略图、JPEG 伴生文件或 RAW 内嵌预览。若受设备协议限制而无法显示，应保留文件条目、显示明确提示，并仍允许导入 RAF 原文件。

不要求 1.0 实现专业 RAW 显影。

### 3.5 照片选择

**选择模式：**

- 长按任意照片进入多选模式。
    
- 点击照片切换选中状态。
    
- 选中照片显示清晰角标。
    
- 顶部显示已选数量。
    
- 支持全选当前筛选结果。
    
- 支持取消全选。
    
- 支持退出多选模式。
    
- 支持在照片预览页面切换选中状态。
    

选择状态在列表与预览之间保持一致。

### 3.6 照片导入

这是 App 最重要的功能之一。

**基本要求：**

1. 支持单张导入。
    
2. 支持批量导入。
    
3. 通过 PTP/MTP 读取原始文件内容。
    
4. 不改变图片画质、分辨率、压缩参数或 EXIF。
    
5. 默认保留原始文件名。
    
6. 导入成功后，照片可以被系统媒体库检索。
    
7. 导入完成后显示实际成功数量。
    
8. 不因单个文件失败而终止全部导入任务。
    

**默认存储策略：**

- JPEG、系统支持的 HEIF 图片：优先保存至 `Pictures/FujiImport/`，并通过 MediaStore 注册。
    
- RAF：保存至系统可访问的公共文件目录，例如 `Download/FujiImport/`，保证用户可以通过文件管理器找到原始 RAW 文件。
    
- 若系统相册不支持识别 RAF，不得声称 RAW 一定会显示在系统相册内。
    

具体目录与媒体注册方式应遵守目标 Android 版本的 Scoped Storage 机制。

**导入进度：**

- 显示当前进度，例如 `12 / 35`。
    
- 显示当前正在导入的文件名。
    
- 显示总体进度条。
    
- 可获得准确字节数时显示当前文件传输进度。
    
- 显示完成、失败、跳过数量。
    
- 支持用户取消尚未完成的导入任务。
    

**重复文件处理：**

导入前检查目标文件是否已经存在。

优先通过文件名、大小、拍摄时间等元数据判断可能重复的文件。无法充分确认时不得仅因文件名相同就认定内容一致。

默认跳过已确认的重复文件；存在名称冲突但内容无法确认时，采用安全重命名，避免覆盖已有文件。

**完整性与异常处理：**

- 使用流式传输，避免把大型原文件整体加载进内存。
    
- 写入期间使用 MediaStore `IS_PENDING` 或等效的安全临时写入机制。
    
- 传输完成后校验目标文件实际大小；必要时进一步校验完整性。
    
- 传输失败、取消或断线时清理未完成的文件。
    
- 仅在完整写入成功后才提示导入成功。
    
- 不得删除或改变相机端的任何照片。
    

### 3.7 导入记录

App 应维护本地导入记录，包括：

- 原始文件名
    
- 文件大小
    
- 原始拍摄时间
    
- 导入时间
    
- 导入结果
    
- 本地文件 URI 或存储位置
    

已成功导入的照片可在相机列表中显示非侵入式标记。

导入记录只用于便利操作，不应作为文件实际存在的唯一判断依据。

## 4. UI / UX 设计

### 4.1 整体风格

采用简洁、现代的原生 Android 视觉设计。

参考 Google Photos、Apple Photos 等应用的照片浏览逻辑，但不直接复制其品牌元素。

**设计要求：**

- 默认适配系统深色、浅色模式。
    
- 优先优化横屏大屏使用体验。
    
- 控件大小适合手指触控。
    
- 减少卡片、边框和无意义装饰。
    
- 尽可能让照片成为视觉主体。
    
- 动画自然、克制。
    
- 所有用户可见文字使用简体中文。
    
- 无广告、启动广告、登录入口及付费界面。
    

### 4.2 页面结构

**页面 A：相机连接页**

未连接相机时显示简洁的连接引导。

连接后自动进入照片列表，不要求额外点击「开始扫描」。

**页面 B：照片列表页**

顶部工具栏包含：

- Fuji Import 标题
    
- 相机连接状态
    
- 卡槽筛选
    
- 排序功能
    
- 刷新按钮
    
- 更多菜单
    

主体为照片网格。

进入多选状态后，底部显示导入操作栏。

**页面 C：照片详情页**

以照片为主体，全屏查看。

顶部可显示返回按钮和照片信息入口，底部提供选择与导入功能。

**页面 D：导入进度界面**

显示批量传输进度、完成数量、失败数量以及取消按钮。

导入完成后显示结果汇总。

**页面 E：设置与诊断**

包含：

- 默认导入目录说明
    
- 缩略图缓存管理
    
- 应用版本信息
    
- USB 设备信息
    
- 连接状态和错误诊断
    
- 导出脱敏诊断日志
    

## 5. USB 与照片访问的技术实现

### 5.1 USB 接口

使用 Android 原生 API：

- `UsbManager`
    
- `UsbDevice`
    
- `UsbDeviceConnection`
    
- `UsbManager.requestPermission()`
    
- USB 设备连接和断开广播
    

App 同时支持启动时扫描现有设备和运行时接收设备插入事件。

不得单纯硬编码富士 USB VID/PID，必须能够检查设备接口类型与协议能力。

### 5.2 PTP/MTP

优先使用 Android `MtpDevice`：

- `open()`
    
- `getDeviceInfo()`
    
- `getStorageIds()`
    
- `getStorageInfo()`
    
- `getObjectHandles()`
    
- `getObjectInfo()`
    
- `getThumbnail()`
    
- `importFile()`
    

通过存储 ID、对象 Handle、对象类型和元数据组织照片列表。

需要正确处理 MTP 对象与文件系统路径之间的差异，不能假设相机暴露为普通 U 盘。

若系统 MTP 实现无法兼容 X-T5，应首先采集真实 USB 描述符、接口与协议响应，并评估是否需要在应用内实现专用 PTP USB 通信适配层。

不允许以要求 Root、修改系统固件或手动复制 SD 卡文件替代原定 USB 直连目标。

### 5.3 并发与资源管理

- USB 通信统一封装到独立的数据访问层。
    
- 通过协程调度控制后台任务。
    
- 限制同时进行的相机读取请求。
    
- 避免缩略图读取与原文件导入相互干扰。
    
- 设备断开时及时取消依赖连接的任务。
    
- 相机重新连接后重新验证对象 Handle。
    
- 所有文件句柄、USB 连接和临时资源必须正确关闭。
    
- 应用切换前后台后可以恢复正常交互。
    

### 5.4 数据安全

相机端必须保持只读。

不得实现或调用相机文件删除、格式化、重命名、写入和覆盖操作。

App 无需互联网权限，不上传任何照片、设备信息或日志。

USB 协议适配代码必须明确区分读取操作与潜在写入操作。

## 6. 性能与稳定性要求

重点保证数千张照片场景下的实用性。

**要求：**

1. 读取至少 1000 张照片时不出现 OOM。
    
2. 支持数千张照片的增量扫描与列表展示。
    
3. 网格滚动保持流畅，不因同步 USB I/O 阻塞主线程。
    
4. 缩略图按需加载，避免启动时下载全部原图。
    
5. 大图预览采用适当的分辨率采样策略。
    
6. 批量导入时显示实时状态。
    
7. USB 意外断开时应用不能闪退。
    
8. 存储空间不足时停止受影响的写入并报告错误。
    
9. 单张照片损坏不能导致整体扫描失败。
    
10. 支持横竖屏切换，关键状态不会意外丢失。
    

对于扫描速度、预览速度和导入吞吐量，记录实机测量值。不得在未验证的情况下承诺固定秒数或传输速率。

## 7. 异常处理

至少完整处理以下场景：

|场景|预期行为|
|---|---|
|相机未连接|显示连接引导|
|USB 权限被拒绝|提示并允许重新申请|
|系统占用 USB 相机接口|提示占用或连接失败原因|
|相机模式不兼容|显示具体排查建议|
|相机无 SD 卡|显示无可用存储|
|SD 卡无照片|显示空相册|
|无法读取某张缩略图|显示占位图，不影响其他照片|
|相机中途断开|停止相关操作，提示重新连接|
|导入空间不足|保留成功文件，报告失败|
|导入时单文件损坏|跳过当前文件，继续处理队列|
|RAF 无法原生解码|显示预览受限，但允许导入|
|应用重启|保留设置和有效导入记录|

错误信息应尽量清晰，不直接将未经解释的异常堆栈展示给普通用户。

## 8. 项目结构与工程要求

推荐使用以下逻辑分层，具体目录由开发时合理组织：

```
app/
 └── src/main/
     ├── java/.../
     │   ├── ui/
     │   │   ├── connection/
     │   │   ├── gallery/
     │   │   ├── preview/
     │   │   ├── import/
     │   │   └── settings/
     │   ├── data/
     │   │   ├── usb/
     │   │   ├── mtp/
     │   │   ├── media/
     │   │   ├── cache/
     │   │   └── repository/
     │   ├── domain/
     │   └── util/
     └── res/
```

**工程要求：**

- 代码结构清晰，功能模块解耦。
    
- UI 不直接处理 USB 底层协议。
    
- 使用统一的数据模型表示照片。
    
- 日志清晰，异常可定位。
